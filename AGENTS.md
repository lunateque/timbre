# Timbre

A modular music server. Every module is written against one kernel and the
whole workspace is kept honest by one command: `just ci`.

## Modules and the kernel

- A module is a crate under `crates/modules/<id>` that exposes
  `pub fn register(registry: &mut Registry) -> Fallible` plus its `log_events`
  and `failures` modules at its root. Registration happens only through
  `registry.module(module::register)`.
- `crates/timbre/src/modules.rs` is generated by
  `cargo xtask module new|remove`; never edit it by hand. Adding or removing a
  module is done only through `cargo xtask module new <id>` and
  `cargo xtask module remove <id>`, which keep the manifest edits, the
  generated wiring and `Cargo.lock` consistent.
- The dependency graph is a star around the kernel: a module depends on
  `timbre-kernel` and edge crates, the binary `timbre` depends on kernel,
  modules and edge crates, edge crates (`crates/edge/<name>`) depend on the
  kernel and on external crates, `xtask` depends on no workspace crate.
- External crates are allowed only in edge crates and in `xtask`, and only when
  listed in `deps.allow`, one line per crate: `<crate-name> <reason it is allowed>`.
  The kernel, the modules and the binary build on std alone.

## Logging

- Everything observable is logged: every request, every failure crossing a
  boundary, every background job's start and end, every external effect, as a
  typed event with the request id when there is one.
- Log events are `LogEvent` constants declared in a crate's `log_events.rs`,
  named `<module>.<snake_case_name>`; the name is checked when the code
  compiles.
- Fields are typed values (`bool`, integers, strings, `Duration`, ...) passed
  as `key = value` pairs; secrets go through `Secret<T>`, which never prints its
  contents.
- The `Ctx` is passed explicitly to everything that logs, publishes signals or
  needs ports; there is no global context.

## Failures

- Failure codes are `FailureCode` constants in a crate's `failures.rs`, named
  `<module>.<snake_case_name>`, declared once in the workspace.
- Errors are hand-written enums implementing `timbre_kernel::Failure` (a stable
  code, an HTTP status and a user-safe message), returned as `Fallible<T>` with
  an explicit `Box::new(...)`; there is no `From` conversion into the box.
- `cargo xtask check` enforces that each code and each event name is declared
  once in the workspace and that every declaration carries the module's prefix.

## Code rules

- No `unsafe`; no `unwrap`, `expect`, `panic!` or indexing outside tests.
- Numeric conversion goes through `From`/`TryFrom`, never a lossy `as`.
- A `.rs` file is at most 400 lines.
- `#[expect(clippy::<lint>, reason = "...")]` only where fixing the code would
  make it worse; the reason says why.
- Comments explain why the code is the way it is. They never narrate a change,
  name who asked for something or quote a conversation.
- Tests: a test must fail on a bug a caller or user would notice. No tests of
  wiring, default values, constants, `Debug` output nobody reads, "does not
  panic", or tests that restate the implementation. Never loosen an assertion
  to make a test pass: fix the code or report the conflict. When a test is
  planned with exact expected output, assert it exactly.
- No files nobody asked for: no summaries, plans, notes or reports in the
  public tree; design documents and plans go to `.internal/` (a separate
  repository, never committed here).

## History

- Work on a local branch; land with `just land <branch>`, which squashes the
  branch onto `main` as one commit, runs `just ci` first and checks the
  message with `cargo xtask commits` afterwards. Without a terminal, pass the
  message as a file: `just land <branch> <message-file>`.
- Commit style (conventional types, subject capitalization, length, the imperative
  mood, no fixup/wip/merge commits) is checked by `committed` with the rules of
  `committed.toml`; `cargo xtask commits` runs it and adds the rest: a body is
  required for `feat`, `fix` and `perf`, no banned phrases, ASCII only, no
  attribution.
- When `land` rejects the message after the squash commit, fix it with
  `git commit --amend`, run `cargo xtask commits HEAD~1..HEAD`, and delete the
  branch with `git branch -D <branch>` by hand; `land` itself stops before
  deleting it.

## Working on this repository

- `just setup` once per clone: enables the hooks and installs the pinned gate
  tools.
- `just ci` passes before a change is done.
- `just fix` applies formatting and machine-applicable clippy fixes.
